# DH制（指名打者制）対応 実装計画

> 2026-05-30 策定 → **2026-06-14 更新**。v1.0.0 初回リリース・審査通過済み。
> 本計画は **次期バージョン v1.1 の目玉機能** として着手する（保留解除）。
> ロードマップ上は SPEC.md の新規項目。

## v1.1 で確定した仕様（2026-06-14 ユーザー指示）

下記が今回の実装で満たすべき要件。詳細は後続セクションに落とし込む。

1. **DHあり/なしの選択は「シーズン開始時・試合数を選ぶのと同じタイミング」**で行う。
   → 設定画面（SettingsScreen）ではなく、**新シーズン開始ダイアログ**（`_NewSeasonDialog`、
   試合数の `SegmentedButton` の隣）に置く。シーズン単位で開始時に確定。
2. **DHなし** → **現在の実装そのまま**（投手が打席に立つ）。新規コードを通さない。
3. **DHあり** → 投手の代わりに野手が打席に入る。
4. **DHは「権利」**。普通は控え野手の方が投手より打てるのでDHを使うが、**大谷型**
   （控え野手の最良より投手の打力が高い選手）は、DHを使わず投手のまま打席に立てる。
5. → **スタメン画面でユーザーがどちらか選べる**。守備位置の選択時に「投手」も「DH」も選べる。
   - **DHを選んだ場合** → 打席に立つのは野手（DH）。**投手は別途選ぶ**必要がある。
   - **投手を選んだ場合** → 大谷型。その投手がそのまま打席に立つ（DHスロットなし）。

## なぜ初回リリースから外したか（経緯メモ・履歴として残す）

> 以下は v1.0.0 に含めなかった判断の記録。**着手判断は済んでいる**ので、いま再検討は不要。
> 「後でマイグレーション地獄になる」シナリオが無い＝今やっても後でやっても作業量は同じ、
> という見立ては v1.1 着手後も有効（下記が後方互換の根拠になる）。

DH対応を初回リリースに**割り込ませる技術的圧力は無かった**。理由:

1. **データ整合性は完全に安全**。DHで永続化するフィールド（リーグの `enableDH`、
   チームごとの「DHを使うか」）は**すべて「追加フィールド + デフォルト値」**。古いセーブに
   無ければ `fromJson` でデフォルトを入れるだけ。本ゲームはローカル保存・同期なし・
   引き継ぎなしで、`ROSTER_EXPANSION_PLAN.md` でも「旧セーブ破棄でよい」方針が確立済み。
   「今やらないと後でマイグレーション地獄」というシナリオは存在しない。
2. **構造的にも局所的**。守備・投手側はすでに打順から分離済み
   （`lineup_planner.dart` の `alignment[FieldPosition.pitcher]`）。投手の特定は
   index 非依存（`team.dart` の `pitcher` getter が `isPitcher` で走査）。DH化は
   「打順リストから投手を抜いてDHを入れる」中心の狭い変更で、アーキテクチャ作り直しではない。
3. **待っても難しくならない**。DHが触る「投手が打つ前提」のコードは既に
   `isPitcher`/getter の裏に隔離されている。現フェーズは新ゲームシステムを足さない
   磨き込み期なので監査対象が増えず、作業量は今やっても後でやっても同じ。

> 逆に「ファーストリリース必須」だったのは **DHあり一本化（強制）** を選んだ場合のみ。
> 後から DHなし→DHあり を強制するとDHなし派にマイナスだから。本計画は**切り替え式**を
> 採るのでこの制約は当たらない（強制変更が起きない）。

## 設計モデル（2段階の権利モデル）

現実の DH制をそのまま再現する。**DHはチームに強制されるルールではなく「権利」**。
「リーグ」レベルは**シーズン開始時（試合数選択と同じダイアログ）に確定**し、そのシーズン中は固定。
「チーム/試合」レベルは**スタメン画面**で試合ごとに選ぶ。

| レベル | 設定 | 効果 |
|---|---|---|
| **リーグ** | DH制 なし | 全チーム強制で投手が打席に立つ（＝**現在の実装**） |
| **リーグ** | DH制 あり | DHは「権利」。各チームが**試合ごと**に使う/使わないを選べる |
| **チーム/試合**（リーグ=ありの時のみ） | DH使う | 野手がDHで打ち、投手は打席に立たない（**通常**。投手は打力が弱いので普通こちら） |
| **チーム/試合**（同上） | DH使わない | 投手がそのまま打席に立つ（**大谷型**。投手が他の野手より打てるなら使わない） |

- デフォルト: **リーグ=DHあり**（現実のトレンド = 高校野球・セ・リーグ・MLB全リーグがDH化。
  切り替え式なのでDHなし派も選べる）。
- 高校野球のように「使うチームと使わないチームが半々」も、この権利モデルで自然に表現できる。

### シミュレーション上は「1チーム1bool」に畳める（実装の肝）

4状態は試合シミュレーションでは **1チームあたり1つの bool** に収束する:

```
その試合で投手が打つか pitcherBats = !(リーグDHあり && そのチームが当該試合でDHを使う)
```

- 「投手をDHスロットに入れる（大谷の二刀流）」と「DHを使わない」は、シミュレーション上は
  **どちらも "投手が打つ・9人で回る" で同一**。違いはUIの見せ方だけ。
- よって**大谷型に特例コードは不要**。`useDH` のオンオフ一本で旧来・通常DH・大谷を全部表現する
  （`feedback_unified_logic_principle` = 特例を増やさない原則に合致）。

### CPU 5球団の扱い

- リーグ=DHありのとき、CPUは**常にDHを使う**（自動生成の投手は打力が低く、現実通り
  「普通はDHを使う」に落ちる）。大谷型がCPUに生成される仕組みは現状なく、不要。
- 将来CPUに大谷型生成を入れたら、その時だけ「投手の打力 > 控え野手最良なら投手が打つ」を
  足す（今は実装しない）。

      → 前述の通り「DHを使わない」と「投手が打つ」は同値なので**特例コード不要**
      （`feedback_unified_logic_principle`）。UIの差（DHタイル vs 投手タイル）として表現するだけ。
- [ ] **試合単位の `useDH` 導出**: スタメンに DH スロットがあれば `useDH=true`、

      DHあり・DH使用なら「打順=8守備位置+DH」かつ「守備投手が別途1人」、

## 大谷（二刀流）の3パターン対応（2026-06-14 実装）

DH制ありリーグ内で、大谷型を 3 通り再現できる:

1. **登板日（投げて打つ）** = スタメンでその選手の守備位置を「投手」にする（`useDH=false`）。
   投手が打順に入り、投げながら打つ。従来の非DH経路と同一。
2. **非登板日（DH で出場）** = その選手を打順に置き守備位置「DH」を選ぶ（`useDH=true`）。
   投手登録の選手でも DH 可。別途「先発投手」カードで実際に投げる投手を指定。
3. **降板後も DH で残る（大谷ルール）** = ①で始めた試合中、投手が降板したとき、
   その投手の打撃（ミート+長打+選球眼）が**控え野手全員より高ければ**、投手→DH に
   転換して打線に残す（新投手はマウンドに立つが打席に立たない）。エンジンが自動判定
   （`game_simulator` の投手交代時 + `TeamFieldingState.setPitcher(keepOldAsDH:)`）。
   適用条件: リーグ DH あり & その試合が大谷型（投手が打席に立つ）& 降板 & 打撃が控え野手より上。

> 実装の肝: 「打順に投手が居る/居ない」では DH 判定できない（投手登録の選手が DH に
> 入るため）。試合用 `Team.usesDH` フラグで明示し、投手の打席用ロジック（先読み降板・
> 代打→投手交代）は「打席の選手 == 攻撃側の現投手本人」のときだけ走らせる。

## 着手時の注意点・メモ

- **最大の注意は `players` の「打順」と「守備9人」の兼用**（`getBatter()` の `% 9`、
  `pitcher`/`pitcherBattingIndex` getter）。DHは「打順=9人（投手抜き+DH）」と「投手」を
  解きほぐす必要がある。守備側は `alignment` で既に分離済みなので、主に**打順リストの
  意味を「打席に立つ9人」に統一**するのが作業の中心。
- フェーズ1を先に通せば、UI未実装でも常に動く状態を保てる（CPU=常時DH / 自チーム=デフォルトDH）。
- 既存の `useDH=false` 経路は**現在のコードそのもの**なので、DHなしリーグ・大谷型は
  リグレッションが出にくい（新規コードはDHあり経路だけ）。
