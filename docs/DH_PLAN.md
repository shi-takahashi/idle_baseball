# DH制（指名打者制）対応 実装計画

> 2026-05-30 策定。**セカンドリリース以降に着手**（ファーストリリースには含めない）。
> 現フェーズ（RevenueCat 連携 + リリース準備）を優先し、本機能は割り込ませない。
> ロードマップ上は SPEC.md の新規項目。`project_phase_focus`（磨き込み優先）に従い後回し。

## なぜ「後回しでよい」と判断したか（最重要・着手前に再確認する）

DH対応を**今すぐやる技術的圧力は無い**。理由を残しておく（後で迷わないため）:

1. **データ整合性は完全に安全**。DHで永続化するフィールド（リーグの `enableDH`、
   チームごとの「DHを使うか」）は**すべて「追加フィールド + デフォルト値」**。古いセーブに
   無ければ `fromJson` でデフォルトを入れるだけ。本ゲームはローカル保存・同期なし・
   引き継ぎなしで、`ROSTER_EXPANSION_PLAN.md` でも「旧セーブ破棄でよい」方針が確立済み。
   「今やらないと後でマイグレーション地獄」というシナリオは存在しない。
2. **構造的にも局所的**。守備・投手側はすでに打順から分離済み
   （`lineup_planner.dart` の `alignment[FieldPosition.pitcher]`）。投手の特定は
   index 非依存（`team.dart` の `pitcher` getter が `isPitcher` で走査）。DH化は
   「打順リストから投手を抜いてDHを入れる」中心の狭い変更で、アーキテクチャ作り直しではない。
3. **待っても難しくならない**。DHが触る「投手が打つ前提」のコードは既に
   `isPitcher`/getter の裏に隔離されている。現フェーズは新ゲームシステムを足さない
   磨き込み期なので監査対象が増えず、作業量は今やっても後でやっても同じ。

> 逆に「ファーストリリース必須」だったのは **DHあり一本化（強制）** を選んだ場合のみ。
> 後から DHなし→DHあり を強制するとDHなし派にマイナスだから。本計画は**切り替え式**を
> 採るのでこの制約は当たらない（強制変更が起きない）。

## 設計モデル（2段階の権利モデル）

現実の DH制をそのまま再現する。**DHはチームに強制されるルールではなく「権利」**。

| レベル | 設定 | 効果 |
|---|---|---|
| **リーグ** | DH制 なし | 全チーム強制で投手が打席に立つ（＝**現在の実装**） |
| **リーグ** | DH制 あり | DHは「権利」。各チームが**試合ごと**に使う/使わないを選べる |
| **チーム/試合**（リーグ=ありの時のみ） | DH使う | 野手がDHで打ち、投手は打席に立たない（**通常**。投手は打力が弱いので普通こちら） |
| **チーム/試合**（同上） | DH使わない | 投手がそのまま打席に立つ（**大谷型**。投手が他の野手より打てるなら使わない） |

- デフォルト: **リーグ=DHあり**（現実のトレンド = 高校野球・セ・リーグ・MLB全リーグがDH化。
  切り替え式なのでDHなし派も選べる）。
- 高校野球のように「使うチームと使わないチームが半々」も、この権利モデルで自然に表現できる。

### シミュレーション上は「1チーム1bool」に畳める（実装の肝）

4状態は試合シミュレーションでは **1チームあたり1つの bool** に収束する:

```
その試合で投手が打つか pitcherBats = !(リーグDHあり && そのチームが当該試合でDHを使う)
```

- 「投手をDHスロットに入れる（大谷の二刀流）」と「DHを使わない」は、シミュレーション上は
  **どちらも "投手が打つ・9人で回る" で同一**。違いはUIの見せ方だけ。
- よって**大谷型に特例コードは不要**。`useDH` のオンオフ一本で旧来・通常DH・大谷を全部表現する
  （`feedback_unified_logic_principle` = 特例を増やさない原則に合致）。

### CPU 5球団の扱い

- リーグ=DHありのとき、CPUは**常にDHを使う**（自動生成の投手は打力が低く、現実通り
  「普通はDHを使う」に落ちる）。大谷型がCPUに生成される仕組みは現状なく、不要。
- 将来CPUに大谷型生成を入れたら、その時だけ「投手の打力 > 控え野手最良なら投手が打つ」を
  足す（今は実装しない）。

## 実装フェーズ（2段階。各段階でゲームが動く状態を保つ）

### フェーズ1: リーグトグル + 試合単位 bool（土台）

これだけで遊びとして成立する。自チームはデフォルトDH使用（投手の打順枠に最良打者を自動充当）、
CPUは常時DH使用。

- [ ] **`SeasonController._enableDH: bool`** を追加（デフォルト `true`）。
      `_gamesPerTeam` / `_offseasonProgressionEnabled` と同じパターン
      （getter / `toJson`・`fromJson` / `commitOffseason` で次シーズンへ継承）。
- [ ] **試合単位の `useDH`** を導出。フェーズ1では「リーグ=あり なら全チーム useDH=true」。
      自チームの試合ごと選択UIはフェーズ2。
- [ ] **`LineupPlanner.buildLineup()`**（`lineup_planner.dart:62-76`）を DH 対応に。
      `useDH=true` のとき `lineup` は **打順9人 = 8野手 + DH（投手を入れない）**、
      投手は `alignment[FieldPosition.pitcher]` にのみ入れる（守備側は現状のまま）。
      DH選手の選定ロジック（誰を打たせるか）が必要。中立モード/能力モードの両対応。
- [ ] **`Team.pitcher` getter**（`team.dart:132`）の堅牢化。DH時は投手が `players` に
      含まれないため、`alignment` または専用フィールドから投手を引けるようにする
      （現在の `return players[8]` フォールバックは DH時に非投手を返すバグになる）。
- [ ] **`Team.getBatter` / `pitcherBattingIndex`**（`team.dart:123,140`）の見直し。
      `players` が「打順9人」を表すよう統一（DH時は投手抜き＋DH）。
- [ ] **`GameSimulator`**（`game_simulator.dart:225-238, 276-278, 328-329`）— `useDH=true` の
      試合は投手の打席の先読み・代打判定・打席スロット差し替えを丸ごとスキップ。
      `useDH=false` の試合は**現状ロジックがそのまま走る**（投手が打つ・終盤に代打）。
- [ ] **`FielderChangeStrategy.decidePinchHit()`**（`fielder_change_strategy.dart:169-248`）—
      投手への代打判定は `useDH=true` ではそもそも投手が打席に立たないので呼ばれない。
      条件分岐が要るか確認。
- [ ] **`SeasonAggregator`**（`season_aggregator.dart:33-39, 287, 299`）— `useDH=true` の試合は
      投手の `batterStats` を作らない/集計しない。`pitcherStats` のみ。年度別履歴
      （`SeasonSnapshot`）は DHあり年/なし年が混在しても per-season なので問題なし。
- [ ] **`SettingsScreen`**（`settings_screen.dart`）に「DH制 あり/なし」トグルを追加
      （`offseasonProgressionEnabled` トグルの近く）。`toJson` に永続化。
- [ ] **`SaveService`**（`save_service.dart`）— 追加フィールドの往復確認。デフォルト値で
      旧セーブ後方互換。
- [ ] 検証 — `test_season` 等でDHあり/なし両方でシーズン完走、`test_persist` でJSON往復。
      リーグ打撃指標を両モードで計測（DHありは得点・打率が上がるのが**正しい挙動**。
      NPBど真ん中からのズレは問題視しない）。

### フェーズ2: 自チームのDHスロット編成UI（大谷再現 + 試合ごと選択）

フェーズ1の上に乗せる後付け。

- [ ] 自チームが**試合ごとに DH を使う/使わないを選べる**UI（編成/作戦画面）。
      デフォルトは前日同様（＝DH使用）。保存先は `next_game_strategy` の拡張が候補
      （ベンチ入り・打順と同じ場所）。
- [ ] **DHスロットに誰を入れるか**をユーザーが選択。野手 → 通常DH。
      **投手を選択 → 大谷（投げて打つ）**。DHを外す → 投手が打席（大谷の「1番ピッチャー」/
      DH不使用）。前述の通りシミュレーション上は「投手をDHに入れる」=「DHを外す」=
      `useDH=false` で同一なので、UI表現の差として実装する。
- [ ] CPUは引き続き自動（常時DH使用）。

## 着手時の注意点・メモ

- **最大の注意は `players` の「打順」と「守備9人」の兼用**（`getBatter()` の `% 9`、
  `pitcher`/`pitcherBattingIndex` getter）。DHは「打順=9人（投手抜き+DH）」と「投手」を
  解きほぐす必要がある。守備側は `alignment` で既に分離済みなので、主に**打順リストの
  意味を「打席に立つ9人」に統一**するのが作業の中心。
- フェーズ1を先に通せば、UI未実装でも常に動く状態を保てる（CPU=常時DH / 自チーム=デフォルトDH）。
- 既存の `useDH=false` 経路は**現在のコードそのもの**なので、DHなしリーグ・大谷型は
  リグレッションが出にくい（新規コードはDHあり経路だけ）。
