### G. シンカーを高速ツーシーム型に

旧設定では `_speedReductions[PitchType.sinker] = 14`（沈む遅球）だったが、近年は
高速シンカーが主流で、ストレートと変わらない球速が出る。シュート（-5 km/h）と
同じ速度低下に揃えた。ゴロ率 0.675・空振り -0.015 の「ゴロで打たせる球」性格は
据え置き。

### H. 外野手のエラー数を守備力ベースで底上げ

外野エラーが少なすぎ（守備力5で 1.00/150試合、上下差 5→0）、推測ゲームとして
守備力を試合結果から推測できる手がかりが弱かった。`ErrorSimulator` の外野エラー
判定を base+線形modifier から **守備力1〜10 の非線形テーブル**に置換
（[feedback_parameter_influence]）。20シーズン計測で守備力5=5.43 / 守備力7=2.63
/ 守備力1=9.90 個/150試合と「ほぼ (10-X) 個」の目標達成。
リーグ全体は 80.2/143 で NPB 上限ぎりぎり、外野エラー比率 14.5% で範囲内。
`bin/measure_outfield_errors.dart` を追加。

### I. 内野エラーを NPB 水準へ削減 + 守備力差を強化

外野調整後の計測で、内野エラーが NPB 比 2倍過剰 + 守備力9 が clamp で頭打ち

### L. 選球眼・長打力の三振/四球/打率への影響を再設計 + 三振絶対値を NPB 水準へ

選球眼の効果が「BB微増 ⇔ K増のトレードオフ」でネット効果ほぼゼロ・選球眼9 でも
K率 17% と本末転倒だった。さらに長打力が三振に効かず、パワーヒッターのフル
スイング感が再現できていなかった。`at_bat_simulator` の確率式を再設計:

- 選球眼: BB増（既存）+ 見逃しストライク減 + 空振り減 + インプレー時アウト率減
  → 「BB↑ / K↓ / 打率↑」の3方向
- 長打力: BB増強化 + 空振り増（フルスイング） → 「BB↑ / K↑ / 長打↑」

方向性修正後、絶対値が高すぎ（選球眼9 で K 98/150試合）→ `_baseProbStrikeSwinging`
0.063→0.055・選球眼K減効果 0.006→0.010 に強化。さらに sweep_batter を「9人全員
同じ能力」から **「対象1人+他標準」** へ改修（出塁連鎖で打席数が膨らむ問題を解消）。

組み合わせ計測でミ9/長7/眼9 が打率 **.426（4割超え！）** と判明、各打率効果が
単純加算で重なり過剰に。複数の調整ラウンドを経て、最終的に:
- `_meetOutModifier`: 0.020→0.018（コンタクト型を打率の主役に）
- `_eyeOutModifier`: 0.012→0.002
- `_powerSingleModifier`: 0.003→0（長打力 → 単打 廃止）
- `_powerDoubleModifier`: 0.005→0.002
- `_powerHomeRunBase` 全体 約 -40%（NPB 投高打低レンジに合わせる）
- `_baseProbOut`: 0.718→0.738

ユーザー実戦データ（長打力9のスラッガーで HR 21-27 本のみ、NPB スラッガー 35-45 本に
届かない）を受けて、sweep_batter の相手投手を変化球 2 種類 → 4 種類に強化（リーグ
平均投手と同等）して計測基準を実戦と一致させ、HR テーブルを +50% 増、ベース
probOut 微減で打率底上げ。

**最終検証（per-player 150試合、sweep_batter.dart、リーグ平均投手）:**

### N. 球速の効きを強化（A投手問題の解消）

- 閾値 153 → **150**（150km/h以上で空振りボーナス立ち上がり）

## 決定事項

| 項目 | 決定 |
|------|------|
| 技術スタック | Flutter |
| データ保存 | ローカルのみ（引き継ぎなし） |
| 課金基盤 | RevenueCat |
| 課金形態 | 月額サブスク（100〜500円） |
| 自前サーバー | 不要 |
| 投手の打順 | 通常 9 番（DH 非採用）。大谷型で他打順も可能（`isPitcher` で識別） |
| 永続化 | JSON ファイル方式（`save.json`）。`SaveService` + `AutoSaver` で 500ms デバウンス自動保存 |
| 年齢の初期分布 | 開幕時 mean 26 / sd 4 / 18-36（生成のみの上限。ゲーム中の age 上限はなし） |
| 引退判定 | 年齢ハードキャップなし。25 歳超 + 能力低下のスコアで決める。能力高いベテランは 40 歳でも残る |
| 成長タイプ | 未実装。全員「普通型」で年齢曲線が動く（早熟/晩成は将来導入） |
| シーズン試合数 | 30 / 90 / 150 から選択可能。デフォルト 30、翌シーズンは前年と同じ値が初期選択 |
| 能力値分布 | 平均 5・標準偏差 1.5 の正規分布で **1〜9** にクリップ（自動生成）。1 ≈ 1% / 5 ≈ 26% / 9 ≈ 1%。**能力値 10 は特別扱いで、自動生成・加齢成長では出現せず、手動編集でのみ到達できる**（ポテンシャル上限も 9） |
| 投手球速 | 平均 147 km/h（NPB 平均）。自動生成は sd 3.0 + clamp [139,156] でだいたい 140〜155 km/h に収束（140 未満・160 超は自動生成されない）。自然成長の上限 158 km/h、編集 UI のみ 165 km/h まで設定可能 |
| 能力ポテンシャル | 隠しパラメータ。生成時に `初期+2.0+gauss(sd=1)` で各能力ごとに上限を確定。10 は initial=10 のみ、それ以外は 9 を上限。新人タイプで bonus 変動（高卒+1.5/大卒0/社会人-0.5） |
| オフシーズン進行 | per-save 設定。デフォルト ON（加齢・引退・新人加入が発生）。OFF にすると「時を止めて」前シーズンと同じ選手・能力で開始。設定画面から切替可能 |
| 犠飛判定 | `AtBatResultType.sacrificeFly`。外野フライで 3 塁走者がタッチアップ生還した場合のみ。打数に含めず、打点・出塁率分母には入る |
| タッチアップ | 3 塁走者と 2 塁走者の同時タッチアップ時、外野手は本塁送球に固定。2 塁走者は無条件で 3 塁到達（ダブルプレー不成立）|
| 失策の内訳 | 内野ゴロ: 捕球失策 60% / 送球失策 40%。外野二塁打エラー: クッション 70% / 送球 30%（→ 三塁打）。外野単打エラー: 送球のみ（→ 二塁打）。外野フライ落球は未実装（プロレベルでは現実的でない） |
| バント解決 | 球ごとループ + カウント遷移。2 ストライクからのファール = スリーバント失敗（三振）。2 ストライクで「バント続行 vs ヒッティング切替」判断（power 依存）。インプレー時は方向抽選 + 守備能力 vs 走力 |
| 球種の種類 | ストレート + 変化球7種（スライダー/カーブ/スプリット/チェンジアップ/シュート/カットボール/シンカー）の計8種類 |
| 投手の持ち球数 | ストレート + 変化球。各変化球を独立保有確率（NPB 2016 投手割合: スライダー88%/カーブ70%/スプリット58%/チェンジ39%/カット27%。シュート・シンカーは画像の49.8%/12.6%だとシンカーが少なすぎるため両者対称に33%）で抽選。**最低2変化球保証**（合計3種類）・最大5変化球。生成質は全変化球共通で平均5 |
| 球種別ゴロ傾向 | 打球タイプは球種依存（`_groundBallShare`）。NPB実測ゴロ率準拠でストレート0.43〜シンカー0.675。シュート・シンカーはゴロ→併殺を奪いやすく、ストレートはフライ・ライナーで一発を食う |
| 持ち球数ボーナス | 球種が多い投手は打者が待ち球を絞れずわずかに有利。持ち球数（3〜8、平均4.5）が基準から離れるほど空振り率・アウト率を小補正（1球種あたり空振り+0.4pt/アウト+0.2pt）。質ほど重要でない隠し味（3↔6球種で防御率~0.5差） |
| 配球ロジック | 同球種連続ペナルティあり。直前まで同じ球種が連続した数に応じて重みを縮小（連続 2 球目 ×0.5 / 3 球目 ×0.25 / 4 球目以降 ×0.1） |
| 球種配分 | 配球重み = 質テーブル（`_breakingSelectionWeight`、値1 0.30〜値10 1.30、得意な球ほど多投）× 球種別の使用頻度重み（`_pitchTypeUsageWeight`、スライダー1.05〜カーブ0.47。同じ質でも球種で投げやすさが違う）。ストレート基本重み 1.35（球速・質で増減）。**質・投球割合・保有確率の3要素を独立に分離**。リーグ配分はストレート46%/スライダー19%/カーブ7%/スプリット8%/チェンジ6%/カット5%/シュート5%/シンカー5% |
| 変化球の質 | 7変化球の質は非線形テーブル `_breakingQualityTable`（値1 −0.16〜値10 +0.205）で空振り・被打率・四球を補正。線形小刻み補正だと配球比率で希釈されて成績に出ないため。ストレート（伸び）は従来どおり線形 |
| 送りバント発動 | 3 塁ランナーがいる状況（1,3塁 / 2,3塁 / 満塁）では発動しない。ヒットで得点できる場面でアウトを増やすメリットが薄いため。スクイズは別作戦扱いで未実装 |
| 打球タイプ分布 | リーグ平均でゴロ ~50% / フライ ~38% / ライナー ~12%（内野ライナー過多解消のためゴロ寄りに調整）。ゴロ率は球種依存（`_groundBallShare`、ストレート 43%〜シンカー 67.5%）で、非ゴロぶんをフライ:ライナー ≒ 76:24 で配分 |
| 内野安打の走者進塁 | 追加進塁なし。1塁→2塁・2塁→3塁・3塁→生還 で固定（内野で処理される打球のため、外野安打のような追加進塁は物理的に発生しない） |
| 内野安打の左右差 | 左打者は一塁に近く内野安打が多い。打球方向の引っ張り（左打者は1・2塁方向＝内野安打になりにくい）と相殺しないよう、左 ×1.40 / 右 ×0.89 の係数で**ネット左/右 ≒ 1.35倍**。リーグ全体の内野安打数は維持（左を増やすだけにせず右を減らす） |
| 単打の走者進塁 | 「2塁→本塁」と「1塁→3塁」を別確率で判定。2塁→本塁は base 0.58（平均走力）で過半数が生還、1塁→3塁は base 0.28。フルカウント（3-2）決着の単打は走者がスタートを切っているため base を引き上げ（2塁→本塁 0.85 / 1塁→3塁 0.62）。打席最終投球時のカウントは `pitches` から算出 |
| 打点ルール | エラー出塁（reachedOnError）または併殺打（isDoublePlay）で得点が入っても打者には打点をつけない（NPB 公式記録規則）。`AtBatResult.runsScored`（実得点・失点用）と `rbiCount`（公式打点）を別フィールドで管理 |
| 併殺打の3塁走者 | 3塁走者ありの併殺打では、3塁走者は併殺の間にホームインする（一般的なフォース併殺の挙動）。1,3塁 / 2,3塁 / 満塁すべて該当。1アウトからの併殺打（3アウトで終了）は除く |
| 「バント失敗」表示 | バント時に守備が先頭走者をアウトにし打者が 1 塁セーフ となるケース（旧表示「野選」）を「バント失敗」と表示。enum 名は JSON 互換のため `fieldersChoice` のまま維持 |
| 死球（HBP） | 投球の独立試行で発生。制球 5 で 0.35%/球、制球-1 ごとに +0.06pt（[0.05%, 1.0%] でクランプ）。打席結果は `AtBatResultType.hitByPitch`、走塁は四球と同じ押し出しのみ、OBP に算入、打数には含めない |
| 送りバント発動 | power 7 以上は base 0 でバントしない（既存）に加え、**打順補正**を導入: クリーンアップ（3,4,5番）× 0.03〜0.08 / 1番 × 0.6 / 2番 × 1.2 / 6〜8番 0.7〜1.1 / 9番 × 1.0。クリーンアップは実質ゼロ |
| 送りバントの走者位置 | **2 塁単独（1 塁空き）は 7 回以降 + 同点 or 1 点差のみ発動**。早い回や大差ではアウトを与えるメリットが薄い。1,2 塁・1 塁単独は序盤でも発動 |
| 代打判断 | 「投手かどうか」では特別扱いせず、**打撃能力（meet+power）と打順**で統一判定。クリーンアップ（3,4,5番）は除外、1番は閾値 `-2` で厳しく、その他は通常閾値。投手は通常 meet/power が低いため自然と代打が成立する。大谷型の高打撃投手は閾値超で代打されない |
| リリーフ投手への代打 | **リリーフ投手（中継ぎ・セットアッパー等）に打席が回ったらリード中でも代打を送る**。「次イニングで交代予定の投手に打席を消費させない」NPB の定石。ベンチに meet+power が明確に上（差 3 以上）の野手がいる場合に発動。**クローザーは対象外**（試合を締めくくる起用なので 8 回登板でもそのまま 9 回まで投げさせる） |
| 投手への代打（先読み判定） | **投手の打席が来たら `PitcherChangeStrategy.preview` を「次の守備イニング頭の context」で呼んで、戻り値が非 null（=交代する判定）なら代打を送る**。先発・リリーフ・クローザー区別なく統一判定。代打候補は `_findReliefPinchHitter`（meet+power 差 3 以上の野手）。代打成立すると `pendingMandatoryChangeReason='代打降板'`、不成立でも `plannedChange` に予約として保存し、次の守備イニング頭で再判定せず実行する |
| 代走の塁選択 | **2 塁にランナーが居る場合は 1 塁の代走判定を行わない**。1,2 塁同時にランナーがいる時の代走は 2 塁側（先行ランナー）に送るのが NPB の定石。例外（2 塁が俊足で 1 塁が明らかに遅く 2 点欲しい場面）は今回は未実装 |
| 投手代打 | 代打が成立した投手は試合から退場。`team_pitching_state.pendingMandatoryChangeReason='代打降板'` がセットされ、次の守備イニング開始時に新投手へ強制交代。`team_fielding_state.pitcherBattingSlot` を介して、PH の居る投手スロットを新投手で直接書き換える（PH は 1 打席限定で退場、簡易な double-switch 代替） |
| 内野ゴロ時の2塁走者進塁 | 打球方向で分岐。**フォースなし（1塁走者なし）**: 一二投捕ゴロは base 0.85 で3塁進塁、三遊ゴロは base 0.15 で基本ステイ（走力 ±0.03/pt）。**フォースあり（1,2塁）**: 三遊ゴロは守備が先頭走者を狙い base 0.45 で3塁封殺 → 打者1塁セーフの野選（`fieldersChoice`）。一二投捕ゴロ・フォースありは従来通り全走者1つ進塁 |
| 野選（fieldersChoice）の表示 | enum `fieldersChoice` は「先頭走者OUT・打者1塁SAFE」の意味でバント失敗とゴロ由来で共用。`AtBatResult.isBunt` で出し分け: バント由来→「バント失敗」、内野ゴロ由来（1,2塁の三遊ゴロ3塁封殺）→「三ゴロ野選」等 |
| 長打力 → 本塁打 | 長打力1ptあたり一律補正（線形）を廃止し、**長打力ごとの非線形テーブル** `_powerHomeRunBase` で本塁打基本確率を決める。上に凸で上下を引き離す（14シーズン計測で規定打席到達者の平均 HR: power4≈7 / power5≈11 / power7≈26 / power9≈40 / power10≈49）。球種・疲労の被長打率補正は `xbhPowerFactor` で長打力に比例させてから加算（弱打者はストレートでも柵越えしにくい）。リーグ全体は SLG .389 / 本塁打 135（143換算）で NPB 水準内 |
| 守備位置による能力傾向 | 野手生成時、守備位置ごとに打撃・走力の**平均をオフセット**（sd 1.5 は維持）。一塁 長打+1.5/走力-2.0、三塁 長打+1.0/走力-1.0/肩+1.0、二塁 長打-1.0/走力+1.5、遊撃 長打-1.0/走力+1.5/肩+1.0、捕手 長打-1.0/走力-2.0/肩+1.0。外野は強打型40%/守備型35%/中距離型25%を抽選。ハード分岐ではないので大型遊撃手・打てる捕手は裾で数%発生。スタメン平均長打 5.02 でリーグ全体は中立 |

## 短いメモ

- 打者一巡時はカンマ区切りで表示（例: `安打, 三振`）
- 2アウトでゴロアウト時は得点が入らないよう修正済み
- 球速は毎球±5kmの変動（中央寄りの分布）
- 野手の調子は隠しパラメータ（UIには出さない）。RecentForm（成績ベース）と役割分担済み
- 球速の編集範囲は 100〜165 km/h（試合内の調子で +5 km/h 揺れて 170 km/h ≒ メジャー最高記録）
- 自チームの SP 自動選出: `_pickFreshestStarter`（コンディション高い順 → 背番号順）
- 他チームの SP: `_selectStarter`（中4日 + エースバイアス + ジッター、リーグ多様性のため別ロジック）
- 後でやりたい: 背番号もチーム編成画面で設定できるようにする
- 選手名のバリエーション拡充（2026-05-17 完了）: `name_data.dart` を苗字50×名前50＝
  2500通り → **苗字250×名前250＝62,500通り**に拡充。`_uniqueName()` はフルネーム重複を
  `_usedNames`（セーブを跨いで蓄積）で排除するため、組み合わせ数が「1セーブで生成
  しうる総選手数の上限」になる。旧 2500 だと約77シーズンで枯渇して StateError、
  かつ50苗字では1リーグで苗字が3〜4回重複していた。const リストなのでアプリ
  アップデートで差し替え可能、既存セーブの選手名は保持される
- 後でやりたい: 試合開始ボタンを「real-time の時刻判定」と組み合わせて、時間が来てたら直接結果へ
