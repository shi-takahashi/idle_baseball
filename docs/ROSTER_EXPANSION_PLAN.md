# ロスター拡張＋ベンチ入り制 実装計画

> 2026-05-18 策定。着手は翌日以降、時間をとって慎重に進める。
> ロードマップ上は PROGRESS.md Phase 5「先発ローテの柔軟運用 + ロスター拡張」に相当。

## 目的（解決したい課題）

**「一度ローテーションを決めると、先発投手の選択権がない」問題**を解決する。
現状は中4日ゲートにより毎日登板可能な先発が実質1人に固定され、ユーザーに
先発を選ぶ余地がない。1チームの選手数を拡張し「ベンチ入り（26人アクティブ枠）」を
導入することで、毎日複数の先発候補から選べるようにし、あわせて編成の戦略性も高める。

現実の NPB は一軍31名・ベンチ入り26名で、1シーズンを通して1軍/2軍を入れ替えながら
戦う（1シーズンに40〜50人が一軍出場）。本ゲームもこれに倣う。

## 確定仕様

### ロスター構成

- **1チーム40人**（背番号 1〜40 で生成）
  - 投手 18 / 野手 22
  - 投手18 の内訳: 先発（ローテ）6 + 救援 12
- **当日ベンチ入り 26人**（先発も26人の一員）
  - 投手 9（当日先発 1 + リリーフ 8）/ 野手 17
- **非アクティブ 14人** = 投手 9（休養中の先発 5 + 救援 4）/ 野手 5
- 「主に普段試合に出るメンバー」≒ 投手14（先発6＋主力救援8）＋ 野手17 ＝ NPB 一軍31 相当

### 先発ローテーション

- ローテは先発6人。**中5日**（登板間隔6日）以上空けないと先発不可
  （`_minDaysBetweenStarts` を 5→6 に変更）
- 先発は毎日「中5日以上空いた投手」から選択。候補は **ローテ通りの1人 + 普段
  ベンチ入りしていない休養中の先発4人 ＝ 計5人** のイメージ
- 通常はローテ通りだが「この投手は打たれてばかりだから次は別の投手を試す」が可能
- リリーフ→先発の配置転換は専用ロジック不要で自然に成立する:
  ベンチ入り中のリリーフはリリーフ登板で間隔が空かない → 先発候補に上がらない。
  一度ベンチから外せば中5日空き、確実に先発指定できるようになる

### ベンチ入り指定（ユーザー操作）

毎日、40人プールから26人を指定する。デフォルトはすべて前日と同じ。

- 野手: スタメンを決める（デフォルト前日）＋ ベンチ入りさせる控え野手を決める（同）
- 投手: 先発を決める（スタメン決定時に同時、現状の先発指定実装を流用）＋
  ベンチ入りさせるリリーフ投手と役割を決める（デフォルト前日）
- 先発選択時、ベンチ入りしていない投手も候補に出る。ベンチ入り外から先発を
  選ぶとその投手が当日26枠に入り、代わりに誰かが外れる（＝出場は常に26人）

### CPU 5球団の自動運用

- 基本「能力上位を自動でベンチ入り・先発は登板間隔順でローテ」
- 全く入れ替えが無いのは不自然なので、**たまにベンチ入りが変わる**
- 能力の高い選手は基本ベンチ入り固定。能力の低い選手が時々ランダムに入れ替わる程度

### オフシーズン

- 引退・新人の人数を 野手2/投手2 → **野手3/投手3** に増やす

### 既存セーブ

- **移行不要**。本ゲームは未リリースで既存データを保持する必要がないため、
  30人ロスターの旧セーブへの後方互換は実装しない（旧セーブは破棄でよい）

## 実装計画（3フェーズ）

各フェーズ終了時に「常にゲームが動く状態」を維持する。

### フェーズA: ロスター40人化 ＋ モデル ＋ CPU自動運用

ここまでで 40人ロスター・全チーム自動運用でシーズン完走できる状態にする。

1. **`Team` モデルの再構成** — 40人ロスターを保持する形へ。
   `players` / `startingRotation` / `bullpen` / `bench` は広範囲から参照されるため
   最も慎重に進める。40人プール（roster）と、そこから派生する当日26人を扱える構造に。
2. **「当日ベンチ入り26人」概念の新設** — 各チームの当日アクティブ枠。
   フェーズAでは全チーム（自チーム含む）をエンジンが自動選定。
3. **`TeamGenerator` を40人生成に** — 投手18（先発6＋救援12）/ 野手22、
   ポジション分布の見直し、背番号 1〜40。
4. **自動ベンチ入り選定ロジック** — 能力・ロールで26人を選定。先発6人ローテを
   中5日で回す。低能力者の稀なランダム入替。
5. **試合シミュレーターへの受け渡し** — 「26人 + 当日先発」で構成したチームを渡す。
   代打・代走・守備交代が26人内で正しく回るか検証。
6. **ローテ変更** — 中4日→中5日（`_minDaysBetweenStarts` 5→6）。
   先発候補プールを40人全体の中5日空きへ。
7. **永続化** — 40人セーブ形式に。後方互換は実装しない。
8. 検証 — `test_season` 等でシーズン完走、`test_persist` で JSON 往復。

### フェーズB: ベンチ入り指定UI ＋ 先発を全プールから選択

1. **`StrategyScreen` にベンチ入り指定を追加** — 野手（スタメン＋控え）、
   投手（ベンチ入り＋役割）。デフォルトはすべて前日と同じ。
2. **先発選択を5候補から** — 中5日空きの投手（非ベンチ入り含む）を候補に。
3. **ユーザー指定がエンジンの自動選定を上書き**（自チームのみ）。
   ベンチ入り指定の保存場所は `next_game_strategy` の拡張が候補。

### フェーズC: オフシーズン調整

1. 引退・新人の人数を 2/2 → 3/3 に。
2. `TeamRebuilder`・`OffseasonScreen` を40人ロスター対応に。
3. スタメン・ロール再編を40人プールで行うよう調整。

- フェーズAを先に通せば、UI 未実装でも常に動く状態を保てる。
